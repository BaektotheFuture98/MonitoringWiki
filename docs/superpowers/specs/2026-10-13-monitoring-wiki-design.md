# MonitoringWiki 설계

작성일: 2026-10-13, 전면 개정: 2026-10-14

## 1. 목적
사람이 승인한 Elasticsearch 장애 보고서(원인·해결 포함)를 LLM이 컴파일해 **원인 → 증상 → 해결방법** 장애 패턴 위키로 축적하고, 외부 에이전트가 MCP로 증상을 질문하면 위키를 근거로 답하게 한다. Karpathy식 LLM Wiki(raw 불변 / LLM이 관리하는 wiki / 스키마 / ingest·query·lint)를 따른다.

## 2. 핵심 결정
- **입력 경로가 둘로 나뉜다.**
  - Ingest: 승인된 **전체 보고서**(결론·원인 판단·권장 조치 포함)만 `raw/`에 저장한다. 제출 자체가 승인이며 승인자 기록은 없다.
  - Query: 결론·원인 판단·권장 조치를 뺀 보고서나 증상 문장. 읽기 전용이며 raw에 저장하지 않고 `occurrences`에 반영하지 않는다.
- **draft/승격 단계 없음.** 승인된 보고서의 내용은 확정으로 위키에 직접 컴파일한다. Claude가 보고서에 없는 내용을 덧붙이면 그 항목만 `(미검증, Claude 추론)`으로 표시하며 기본은 덧붙이지 않는다.
- 입력은 비정형 텍스트이며 MCP 서버를 통해 들어온다. 위키 본문은 한국어.
- 검색은 LLM이 `wiki/index.md`를 읽고 의미로 후보를 골라 후보 페이지만 여는 방식이다(벡터 DB 없음). 규모가 수백 패턴을 넘으면 qmd 같은 로컬 검색 도구를 검토한다.
- 질문 입력과 ingest 입력은 분리한다. 질문 기록이 필요하면 raw가 아니라 서버 접근 로그로 둔다.

## 3. 디렉터리 구조
```
MonitoringWiki/
├─ AGENTS.md                 # 운영 규칙(스키마)
├─ raw/YYYY-MM-DD/HHMMSS.txt # 불변 원본 (수신 날짜·시각 명명, 같은 초는 HHMMSS-2.txt)
├─ wiki/
│  ├─ index.md               # 통합 색인: 패턴 1개 = 1행(요약, 리소스, 대표 시그니처, confidence, last_seen) + 인프라 링크
│  ├─ log.md                 # 시간순 작업 기록
│  ├─ _template.md
│  ├─ infra/                 # 클러스터 구성(현재 상태, 덮어쓰기, as_of, 노드명·IP 제외, 랙은 티어별 기재, 매일 바뀌는 값 제외)
│  └─ patterns/              # 장애 패턴
└─ docs/superpowers/specs/
```
- 리소스(`query | master | data | slowlog`)는 파일명이 아니라 내용에서 ingest 단계에 판별하며, 한 파일에 여러 리소스가 섞일 수 있다.
- 색인은 `index.md` 하나다. (구 `symptoms-index.md`, `by-resource/*`는 통합 후 삭제)

## 4. 패턴 페이지 형식
frontmatter: `id`(= 파일명, kebab-case), `summary`(증상·원인 한 줄 요약, 색인에 그대로 옮김), `confidence`(`low|medium|high`), `resources`, `first_seen`, `last_seen`, `occurrences`, `sources`(raw 경로), `solution_origin`(`report|human|claude-inferred|official-doc`).
본문 순서: `원인` / `증상`(리소스별) / `해결방법` / `관련 패턴`.
증상의 `미관측`은 `(수집 실패)`, `(이벤트 없음)`, `(입력 없음)`, `(로그 없음)`으로 이유를 구분한다. 원인을 알 수 없으면 "미상"과 확인된 사실만 적는다. 위키 페이지에는 개인정보(이메일, 회사명, 검색 키워드, IP)를 치환해 쓰고 raw는 원문을 보관한다(사용자 승인).

## 4-1. 지식 종류 구분과 처리 (2026-10-15 정립)
| 종류 | 쓰는 곳 | 출처 | 갱신 방식 |
|---|---|---|---|
| 원본 | `raw/` | MCP `submit_report`(서버가 저장만) | 추가만 |
| 패턴 | `wiki/patterns/` | 승인된 보고서를 Claude가 컴파일 | 발생 누적 |
| 인프라 | `wiki/infra/` | 담당자의 대화 설명(사람 설명이 있을 때만) | 덮어쓰기, `as_of` 갱신 |

- 구분 기준: 장애 없이도 참인 현재 상태면 인프라, 특정 장애에서 관측된 증상·원인·해결이면 패턴. 어느 쪽도 아니면 담당자에게 확인.
- 보고서 안의 구성 정보는 인프라를 자동 갱신하지 않고 Ingest 결과 보고에 "인프라 갱신 후보"로만 목록화한다. 보고서와 인프라 페이지가 다를 때 어느 쪽이 맞는지 판단하거나 시각을 비교하지 않고 다름만 보고한다.
- 패턴 페이지는 구성 내용을 복사하지 않고, 인프라는 증상 해석의 참고 맥락일 뿐 패턴 일치 판단의 근거로 쓰지 않는다.

## 5. 워크플로
**Ingest**: raw 저장 → 리소스·로그 원문·보고서 판단·도구 해석 구분 → 시그니처 추출 → `index.md`를 읽고 기존 패턴과 의미 매칭. 매칭되면 `occurrences`/`last_seen`/`sources`/증상 갱신(다른 원인·해결은 덮어쓰지 않고 병기하고 호출자에게 알림). 불일치면 새 패턴 생성(원인=보고서 원인 판단, 해결=권장 조치, `solution_origin: report`). 보고서가 연관을 제시하면 한 패턴, 아니면 분리하고 "동시 관측, 연관 미확인"으로 링크. 마지막으로 `index.md`와 `log.md` 갱신.

**Query**(읽기 전용): 입력을 리소스별로 분해해 시그니처 추출 → `index.md`를 끝까지 읽고 시그니처별로 후보 선택(첫 일치에서 멈추지 않고 모든 시그니처가 설명되거나 "일치 없음"으로 확정될 때까지, 후보 페이지만 열람) → 답변에 일치 근거, `confidence`, `(미검증)` 표시 유지. 일치가 없으면 "알려진 패턴 없음". 필요 시 `위키 외 추론(미검증)`을 분리해 덧붙인다.

**Lint**: 고아 페이지, 깨진 링크, 색인 불일치, 페이지와 `sources` 보고서의 서술 불일치, 오래된 인프라 페이지, 노드명·IP 기재, 중복 의심 패턴, confidence 대비 증거 부족.

## 6. 저장소와 변경 이력
> PoC(2026-10-15)에서는 git 없이 파일로 읽고 쓰며 컴파일은 서버가 자동으로 한다(`2026-10-15-poc-auto-compile-api-design.md`). 아래 git 운영은 PoC 이후 `GitWikiStore`로 적용한다.

- 위키 저장소는 git으로 변경 이력을 남기고 봇(Claude)이 직접 커밋한다. 승인은 입력 단계에서 이뤄지므로 PR 리뷰는 필수가 아니며 선택적으로 쓸 수 있다.
- **`raw/`는 git에 넣지 않는다**(`.gitignore`). 개인정보가 git 이력과 원격에 영구히 남지 않게 하기 위함이며, raw는 서버 디스크에 두고 백업을 따로 한다.
- 컴파일 결과는 `main`에 커밋해야 MCP 조회에 반영된다(MCP 서버는 `main`의 커밋된 상태만 읽음).
- 원격 저장소(GitHub/GitLab 등)는 미정이다.

## 7. MCP 도구 인터페이스 (상세: `2026-10-14-mcp-server-design.md`)
| 도구 | 방향 | 설명 |
|---|---|---|
| `submit_report(text)` | 쓰기 | 승인된 전체 보고서를 raw에 저장하고 서버가 자동 컴파일(PoC). `submit` 토큰은 승인 주체에게만 발급 |
| `get_index()` | 읽기 | `wiki/index.md` 전체 반환(v1은 필터 없음). 후보 선택은 외부 에이전트의 LLM이 판단 |
| `get_pattern(id, sections?)` | 읽기 | 패턴 페이지(또는 일부 섹션) 반환, `sources` 제외 |
| `get_infra()` | 읽기 | `wiki/infra/cluster.md` 반환 |

- **설계 원칙**: MCP는 검색·매칭 판단을 하지 않는다. 문자열 매칭으로 후보를 돌려주면 LLM Wiki가 아니라 검색 DB가 되므로, 색인과 페이지를 읽어 주기만 하고 후보 선택과 답변은 LLM이 한다.
- **컨텍스트**: 도구가 반환한 내용은 호출한 외부 에이전트의 컨텍스트에 모두 들어간다. 색인 행 전체가 먼저 들어오고 페이지는 외부 에이전트가 고른 것만 들어온다. 색인이 커지면 `resource` 필터, 개수 제한, 페이지 나누기를 쓴다.
- **규칙 전달**: Query 규칙(의미 판단, 첫 일치에서 멈추지 않기, 일치 근거 표기, 미검증 표시 유지)은 외부 에이전트에게 자동 적용되지 않으므로 MCP 서버 instructions 등으로 전달한다.
- 승인 권한 분리: 외부 에이전트의 질문 경로(읽기 도구)와 ingest 경로(`submit_report`)는 별도 권한으로 둔다.
